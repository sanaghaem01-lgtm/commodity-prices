# دیدبان قیمت جهانی کالا

**داشبورد:** https://sanaghaem01-lgtm.github.io/commodity-prices/

**درباره‌ی داده‌ها** (منبع، زمان به‌روزرسانی و آخرین تغییر هر بخش):
https://sanaghaem01-lgtm.github.io/commodity-prices/about.html

> هر بار که `style.css` یا `iran-common.js` عوض می‌شود، عدد `?v=...` در آدرس آن‌ها در فایل‌های HTML هم باید
> عوض شود؛ وگرنه مرورگرها تا چند دقیقه نسخه‌ی قدیمی را نشان می‌دهند.

## این سیستم چه می‌کند؟

- قیمت **10 کالا** (قهوه، کاکائو، شکر، ذرت، برنج، روغن کلزا، گوشت گاو، پنبه، لاستیک) از **Pink Sheet بانک جهانی**
  گرفته می‌شود که حدود 1 ماه تأخیر دارد؛ بقیه از FRED. کالایی که در `config/commodities.json` کلید `"worldbank"` دارد
  از بانک جهانی می‌آید. فقط کالایی را به بانک جهانی ببرید که سری‌اش با FRED دقیقاً یکی باشد.
- هر **دوشنبه** به‌طور خودکار قیمت جهانی کالاها را از سایت رسمی
  [FRED](https://fred.stlouisfed.org/) (بانک فدرال رزرو سنت‌لوئیس، داده‌های IMF) می‌گیرد.
- قیمت‌ها را به **دلار بر تن** تبدیل می‌کند (مثلاً قیمت قهوه که «سنت بر پوند» است، ضرب در 22.046).
- نتیجه را در دو فایل ذخیره می‌کند:
  - `data/prices.json` برای داشبورد
  - `data/prices.csv` برای Google Sheets و Excel
- کالاها در **گروه‌ها** دسته‌بندی شده‌اند (مثلاً غلات، روغن‌ها). داشبورد برای هر کالا این‌ها را نشان می‌دهد:
  آخرین قیمت، تغییر نسبت به ماه و سال قبل، کمترین و بیشترین 2 سال اخیر، نمودار روند و یک خلاصه‌ی متنی.
  در هر گروه می‌شود همه‌ی کالاها را با هم مقایسه کرد (درصد تغییر).
- لینک یک گروه را می‌شود مستقیم فرستاد: کافی است گروه را در داشبورد انتخاب کنید و آدرس صفحه را کپی کنید.
- برای قیمت **روزانه**‌ی بورس، راهنمای [فهرست پیگیری TradingView](docs/tradingview-watchlist.md) را ببینید.

> قیمت‌ها **مرجع جهانی** و **ماهانه** هستند و معمولاً با 1 تا 2 ماه تأخیر منتشر می‌شوند.
> با قیمت فیزیکی تأمین‌کننده فرق دارند. این سیستم خودش پیش‌بینی نمی‌کند (پیش‌بینی‌ها از بانک جهانی است) و توصیه‌ی خرید نمی‌دهد.

> ⚠️ این مخزن و داشبورد **عمومی** هستند و همه می‌توانند آن‌ها را ببینند.
> هیچ‌وقت قیمت تأمین‌کننده، نام مشتری یا تأمین‌کننده، یا اطلاعات مالی شرکت را اینجا نگذارید.

## چطور کالای جدید اضافه کنیم؟

1. شناسه‌ی کالا را در FRED پیدا کنید: در سایت fred.stlouisfed.org نام کالا را جستجو کنید
   (مثلاً `Global price of Swine`). شناسه کنار عنوان صفحه نوشته شده، مثلاً `PPORKUSDM`.
   سری‌هایی را انتخاب کنید که **Monthly** هستند.
2. در GitHub فایل `config/commodities.json` را باز کنید و روی آیکون مداد (Edit) بزنید.
3. یک خط شبیه خط‌های قبلی اضافه کنید. **دقت کنید که بعد از خط قبلی یک ویرگول (`,`) باشد**:
   ```json
   {"fred_id": "PPORKUSDM", "category": "گوشت و آبزیان", "name_fa": "گوشت خوک", "name_en": "Swine", "color": "#008300", "tradingview_symbol": "CME:HE1!"}
   ```
   - `category` نام گروه است. **دقیقاً** همان نوشته‌ی گروه‌های موجود را کپی کنید تا کالا در همان گروه بیاید؛
     اگر نام تازه‌ای بنویسید، یک گروه جدید ساخته می‌شود.
   - ترتیب کالاها و گروه‌ها در داشبورد همان ترتیب این فایل است.
   فیلد `tradingview_symbol` **اختیاری** است: اگر کالا در بورس معامله می‌شود، نماد TradingView آن را بنویسید
   تا دکمه‌ی «قیمت روزانه‌ی بورس» برایش ساخته شود. اگر نماد بورسی ندارد (مثلاً خشکبار)، این قسمت را حذف کنید.
4. **Commit changes** را بزنید.
5. به تب **Actions** بروید و workflow را دستی اجرا کنید (پایین‌تر توضیح داده شده).

**رنگ:** در هر گروه رنگ‌ها به این ترتیب استفاده می‌شوند؛ برای کالای جدید، اولین رنگی را بردارید
که هنوز در **همان گروه** استفاده نشده:
`#2A78D6` (آبی)، `#EB6834` (نارنجی)، `#1BAF7A` (سبزآبی)، `#EDA100` (زرد)، `#E87BA4` (صورتی)،
`#008300` (سبز)، `#4A3AA7` (بنفش)، `#E34948` (قرمز). هر گروه حداکثر 8 کالا داشته باشد تا نمودار مقایسه خوانا بماند.

اگر واحد کالای جدید برای برنامه ناشناخته باشد، workflow با خطا تمام می‌شود و می‌گوید کدام واحد را نمی‌شناسد.
در این حالت تبدیل آن واحد باید در فایل `scripts/units.py` اضافه شود.

## اگر به‌روزرسانی متوقف شد کجا را ببینیم؟

1. در صفحه‌ی مخزن در GitHub روی تب **Actions** بزنید.
2. در فهرست، اجراهای **Update prices** را می‌بینید:
   - ✅ سبز = موفق
   - ❌ قرمز = خطا. رویش کلیک کنید، بعد روی **update**، و مرحله‌ای را که قرمز است باز کنید تا متن خطا را ببینید.
3. اگر یک یا چند کالا خطا بدهند، **داده‌ی قبلی همان کالاها پاک نمی‌شود**، بقیه‌ی کالاها به‌روز می‌شوند
   و اجرا قرمز می‌شود تا خطا دیده شود. متن خطا نام کالای مشکل‌دار را می‌گوید.
   اگر مشکل چند ماه ادامه پیدا کند، بالای داشبورد هم یک هشدار قرمز ظاهر می‌شود.
4. GitHub برای خطاها به ایمیل صاحب مخزن هم پیام می‌فرستد.

**خطاهای رایج:**

| پیام خطا | معنی | چه کنیم |
|---|---|---|
| `کلید FRED_API_KEY تعریف نشده است` | Secret تعریف نشده | بخش «کلید API» را ببینید |
| `HTTP 400 ... api_key` | کلید اشتباه یا باطل شده | کلید جدید بگیرید و Secret را عوض کنید |
| `واحد ناشناخته` | کالای جدید واحدی دارد که برنامه نمی‌شناسد | تبدیلش باید به `scripts/units.py` اضافه شود |
| `آخرین داده ... روز پیش` | FRED آن سری را مدتی است به‌روز نکرده | در سایت FRED وضعیت آن سری را بررسی کنید |

**اجرای دستی:** تب **Actions** ← در سمت چپ **Update prices** ← دکمه‌ی **Run workflow** ← دوباره **Run workflow**.

اگر در هفته‌ای داده‌ی جدیدی منتشر نشده باشد، workflow موفق (سبز) تمام می‌شود ولی چیزی commit نمی‌کند. این طبیعی است.

## کلید API کجاست و چطور عوضش کنیم؟

کلید FRED **فقط** در GitHub Secrets نگه داشته می‌شود، نه در هیچ فایلی.

**برای عوض کردن کلید:**
1. در fred.stlouisfed.org وارد حساب شوید ← **My Account** ← **API Keys** ← یک کلید جدید بسازید.
2. در GitHub، صفحه‌ی مخزن ← **Settings** ← **Secrets and variables** ← **Actions**.
3. کنار `FRED_API_KEY` روی آیکون مداد بزنید، کلید جدید را بچسبانید و **Update secret** را بزنید.
4. در FRED کلید قدیمی را حذف کنید.
5. workflow را یک بار دستی اجرا کنید تا مطمئن شوید کار می‌کند.

⚠️ کلید را هیچ‌وقت در فایل، ایمیل، چت یا پیام کپی نکنید.

## اتصال به Google Sheets و Excel

آدرس فایل CSV:

```
https://sanaghaem01-lgtm.github.io/commodity-prices/data/prices.csv
```

ستون‌ها: `date, commodity, price_original, unit_original, usd_per_ton`

**Google Sheets:** در یک خانه‌ی خالی (مثلاً A1) بنویسید:
```
=IMPORTDATA("https://sanaghaem01-lgtm.github.io/commodity-prices/data/prices.csv")
```
Google Sheets هر چند ساعت یک بار خودش فایل را دوباره می‌خواند.

**Excel:** منوی **Data** ← **From Web** ← آدرس بالا را بچسبانید ← **Load**.
برای به‌روز کردن: **Data** ← **Refresh All**.

داده فقط از این مخزن به بیرون می‌رود. Google Sheet یا Excel شما هیچ چیزی به این مخزن برنمی‌گرداند،
پس قیمت تأمین‌کننده‌ها و اطلاعات داخلی را با خیال راحت در فایل **خصوصی** خودتان نگه دارید.

## هشدارها و پیش‌بینی بانک جهانی

- **هشدارها** (بالای صفحه‌ی قیمت جهانی، برای گروه انتخاب‌شده): تغییر ماهانه‌ی 10% یا بیشتر، رسیدن به بالاترین یا
  پایین‌ترین قیمت 2 سال، یا 4 ماه پیاپی در یک جهت. فقط واقعیت آخرین ماه است، پیش‌بینی نیست.
  آستانه‌ها در `index.html` (`ALERT_MOVE` و `ALERT_STREAK`).
- **پیش‌بینی بانک جهانی** (پایین هر کارت، برای 14 کالا): میانگین سالانه‌ی 2026 و 2027 از گزارش
  Commodity Markets Outlook. فایل: `config/forecasts.json`.
  **دو بار در سال (آوریل و اکتبر) باید با نسخه‌ی جدید گزارش به‌روز شود** — عددها را از جدول 1 گزارش بردارید
  و دلار بر کیلوگرم را ضرب در 1000 کنید. فقط کالاهایی آمده که سری بانک جهانی با سری داشبورد یکی است.

## تقویم برداشت و صید

- در داشبورد اصلی، برای هر گروه کالا، ماه‌های برداشت یا صید (فصل اصلی و دوم) در کشورهای تولیدکننده‌ی اصلی نشان داده می‌شود
  و ماه جاری علامت دارد. ماه‌ها تقریبی‌اند (منابع: USDA FAS، ICO، ICCO).
- همه‌چیز در `config/harvest.json` است. برای اضافه کردن یک ردیف، یک خط شبیه بقیه اضافه کنید:
  `category` همان نام گروه در `config/commodities.json`، و `main` / `second` شماره‌ی ماه‌های میلادی (1 تا 12).

## اخبار هفته

- هر **دوشنبه و پنجشنبه** (workflow جداگانه‌ی **Update news**) تیتر خبرهای 7 روز اخیر از خبرخوان (RSS) منابع معتبر
  (ناشران باسابقه‌ی صنعت غذا و کالا و سازمان بین‌المللی کاکائو) خوانده می‌شود
  و برای هر گروه حداکثر 6 خبر در داشبورد نمایش داده می‌شود. فقط تیتر، منبع، تاریخ و لینک ذخیره می‌شود.
- خبری انتخاب می‌شود که **نام یکی از کالاهای گروه در تیترش** باشد. خبرهای مربوط به بازار
  (قیمت، برداشت، صادرات…) اول می‌آیند و از هر منبع حداکثر 2 خبر در هر گروه.
- لینک **گزارش‌های رسمی ماهانه** (FAO، ICO، ICCO، IGC، WASDE، ICAC) هم در همین بخش است.
- همه‌ی این‌ها در فایل `config/news.json` تعریف شده‌اند:
  - **اضافه/حذف منبع:** یک خط در بخش `sources` با نام و آدرس خبرخوان (`url`).
  - **کلیدواژه‌ها:** بخش `keywords`؛ نام گروه‌ها باید **دقیقاً** مثل `config/commodities.json` باشد.
    اگر کالای جدیدی اضافه کردید، نام انگلیسی‌اش را به کلیدواژه‌های گروهش هم اضافه کنید.
  - **گزارش‌های رسمی:** بخش `reports`.
- اگر یکی دو منبع جواب ندهند، بقیه استفاده می‌شوند و اجرا سبز می‌ماند (هشدار در متن اجرا).
  اگر **بیش از نیمی** از منبع‌ها جواب ندهند، خبرهای قبلی می‌ماند و اجرا قرمز می‌شود.
  مشکل اخبار هیچ اثری روی قیمت‌ها ندارد.

## صفحه‌های ایران

- **بازار ایران** (نمای سریع): https://sanaghaem01-lgtm.github.io/commodity-prices/iran.html
  — نشانه‌های بازار.
- **آمار واردات ایران** (جزئیات): https://sanaghaem01-lgtm.github.io/commodity-prices/iran-imports.html
  — آمار گمرک و آمار کشورهای صادرکننده.

در هر دو صفحه کالا یک بار از دکمه‌های بالای صفحه انتخاب می‌شود و انتخاب بین دو صفحه یادش می‌ماند.
فهرست این کالاها (و کد تعرفه‌شان) در `config/iran_signals.json` است.

- **نشانه‌های بازار ایران** (برای ذرت، برنج، قهوه، کاکائو و روغن): سه نشانه کنار هم —
  جریان واردات 3 ماه اخیر در برابر همین ماه‌ها در سال‌های قبل، تقویم تقاضای ایران (نوروز، رمضان، محرم، …)
  و الگوی ماهانه‌ی واردات از آمار گمرک. پیش‌بینی یا توصیه‌ی خرید نیست.
  - رویدادهای تقاضا و تاریخ‌هایشان: `config/iran_demand.json` — **تاریخ رمضان و محرم هر سال باید تمدید شود**
    (الان تا خرداد 1407 / ژوئن 2028 وارد شده است).
- **واردات ایران (آمار آینه‌ای UN Comtrade):** مقداری که کشورهای صادرکننده گزارش داده‌اند به ایران فروخته‌اند،
  کشورهای اصلی و میانگین قیمت هر تن در برابر قیمت جهانی. فعلاً **ذرت و برنج** (پوشش بقیه‌ی کالاها در این آمار
  خیلی ناقص است). workflow **Update Iran imports** هر دوشنبه اجرا می‌شود؛ کلید در Secret با نام `COMTRADE_API_KEY`.
  کالاها و کد تعرفه‌شان (HS) در `config/iran_imports.json` هستند.
  کالایی که از راه کشور واسطه (مثلاً امارات) یا از کشوری که گزارش نمی‌دهد (مثلاً روسیه) آمده، در این آمار نیست.
- **آمار گمرک ایران** (از سامانه‌ی آمار اتاق بازرگانی تهران): برای هر کالا و هر سال شمسی، مقدار، ارزش، میانگین قیمت هر تن،
  کشورهای طرف معامله، گمرکات ورودی و تفکیک کد تعرفه. workflow **Update Iran customs** روز 3 هر ماه اجرا می‌شود و
  سال‌های تازه را خودش اضافه می‌کند. کالاها (4 رقم اول کد تعرفه) در `config/iran_customs.json` هستند.
  آمار گمرک با تأخیر زیاد منتشر می‌شود (مهر 1405: آخرین سال موجود 1403، فقط جمع سالانه).
- سایت‌های دولتی ایران (گمرک، بورس کالا، مرکز آمار، …) از سرورهای GitHub در دسترس نیستند؛
  آمار گمرک از سامانه‌ی اتاق بازرگانی تهران گرفته می‌شود که از بیرون ایران در دسترس است.

## برای فرد فنی

| فایل | کار |
|---|---|
| `config/commodities.json` | فهرست کالاها |
| `config/news.json` | منبع‌های خبر، کلیدواژه‌ها، گزارش‌های رسمی |
| `scripts/fred_source.py` | گرفتن داده از FRED |
| `scripts/worldbank_source.py` | گرفتن داده از Pink Sheet بانک جهانی (فایل Excel ماهانه؛ آدرسش هر بار از صفحه‌ی بانک جهانی پیدا می‌شود) |
| `scripts/units.py` | تبدیل واحد به دلار بر تن |
| `scripts/fetch_prices.py` | برنامه‌ی اصلی: بررسی سلامت داده و نوشتن خروجی‌ها |
| `scripts/fetch_news.py` | خواندن خبرخوان‌ها و ساختن `data/news.json` |
| `tests/` | تست‌ها: `python3 -m unittest` |
| `.github/workflows/update-prices.yml` | اجرای هفتگی (دوشنبه 06:00 UTC) و دستی |
| `.github/workflows/update-news.yml` | اخبار؛ دوشنبه و پنجشنبه 06:30 UTC و دستی |
| `.github/workflows/update-iran-imports.yml` | آمار آینه‌ای واردات ایران؛ هفتگی (دوشنبه 07:00 UTC) و دستی |
| `.github/workflows/update-iran-customs.yml` | آمار گمرک ایران؛ ماهانه (روز 3، ساعت 08:00 UTC) و دستی |
| `iran.html`، `iran-imports.html`، `iran-common.js`، `style.css` | صفحه‌های ایران، کد مشترکشان و ظاهر مشترک همه‌ی صفحه‌ها |
| `about.html` | صفحه‌ی «درباره‌ی داده‌ها» (اگر منبع یا زمان‌بندی عوض شد، این صفحه هم باید اصلاح شود) |
| `index.html` | داشبورد (Chart.js، بدون فریم‌ورک) |

اجرای محلی:
```
read -s "FRED_API_KEY?FRED key: " && export FRED_API_KEY && echo && python3 -m scripts.fetch_prices
python3 -m http.server 8000   # بعد http://localhost:8000
```
